📖 Introduction

What is a Graph?

Graphs model real-world connections. A graph G = (V, E) has vertices (V) — entities like cities or users — and edges (E) — connections between them. This page covers every major graph type with diagrams, analogies, and traversal examples.

⬡
Undirected Graph
Bidirectional Edges

In an undirected graph, every edge is a two-way street. If A connects to B, then B equally connects to A. There are no arrows — just plain lines.

🤝
Real-World Analogy
Facebook friendships. If Alice is friends with Bob, Bob is automatically friends with Alice. The connection is symmetric — it works both ways with no distinction.
Key Properties
  • ● Edge (A, B) = Edge (B, A) — the same edge, no direction
  • ● Each node has a degree = number of edges attached to it
  • ● Sum of all degrees = 2 × |E| (Handshaking Lemma)
  • ● No arrowheads — drawn as plain lines between nodes

BFS Traversal from A
1Start at A. Queue: [A]. Visited: {A}
2Dequeue A → enqueue neighbours B, C. Queue: [B,C]
3Dequeue B → enqueue D, E. Queue: [C,D,E]
4Dequeue C → E already queued. Queue: [D,E]
5Dequeue D, then E. Queue: [ ] — Done!
BFS Order: A → B → C → D → E  |  Shortest A→E = 2 hops

Directed Graph (Digraph)
One-Way Edges (Arrows)

In a directed graph (digraph), every edge is an arrow pointing from one node to another. A→B does not mean B→A.

🛣️
Real-World Analogy
One-way streets. A road from Town Hall → Station doesn't mean you can drive back the same way. Twitter follows work the same — you can follow someone without them following you back.
Key Properties
  • ● In-degree: arrows pointing INTO a node
  • ● Out-degree: arrows pointing OUT of a node
  • ● Edge A→B ≠ Edge B→A — they are two different edges
  • ● Drawn with arrowheads on one end of each edge
Web Page Links Twitter Follows Task Scheduling Compiler Flow
5 nodes · 5 directed edges · arrowheads show direction
DFS Traversal from A
1Push A onto stack. Stack: [A]
2Pop A, visit. Follow A→B (deeper). Stack: [C, B]
3Pop B, visit. B→D. Stack: [C, D]
4Pop D — no outgoing. Backtrack. Stack: [C]
5Pop C → visit E. Stack: [ ] — Done!
DFS Order: A → B → D → C → E
Type 3
⚖
Weighted Graph
Edges carry numeric costs

A weighted graph assigns a numeric value (weight) to each edge — representing cost, distance, time, or bandwidth. The shortest path = minimum total weight, not fewest edges.

🗺️
Real-World Analogy
Google Maps. Cities are nodes, roads are edges, and edge weights are driving times. You don't want the fewest roads — you want the fastest total journey. That's exactly what Dijkstra's algorithm computes.
Key Properties
  • ● Every edge has a number (weight / cost) written on it
  • ● Shortest path = minimum sum of edge weights
  • ● Can be directed or undirected
  • ● Negative weights break Dijkstra — use Bellman-Ford instead
GPS Navigation Network Bandwidth Flight Routes Supply Chain
Weights on edges · thick line = preferred (cheap) path
Dijkstra from S — step by step
1Init: dist[S]=0, all others=∞. Push (0,S) to heap.
2Pop S. Relax S→A: dist[A]=4. Relax S→B: dist[B]=2.
3Pop B (min=2). B→A: 2+1=3 < 4 → update dist[A]=3.
4Pop A (min=3). A→T: 3+5=8 → dist[T]=8.
5Pop T (min=8). Settled. Done!
S → B → A → T  (cost = 8)  — not the direct S→A→T (cost 9)!

⊙
Cyclic vs Acyclic Graph
Loops vs No Loops

A cyclic graph has at least one cycle — a path from a node back to itself. An acyclic graph has no cycles. A DAG (Directed Acyclic Graph) is directed with no cycles — used for task ordering.

🔄
Real-World Analogy
Cyclic: A circular bus route — you end up back at the starting stop. Acyclic (DAG): A family tree — parents always come before children, no going backwards in generations.
Key Properties
  • ● Cyclic: following edges can return you to the start node
  • ● Acyclic: no path leads back to any visited node
  • ● DAG: directed + acyclic → enables topological sorting
  • ● DFS detects cycles using a "currently in stack" check

DFS Cycle Detection (directed graph)
1DFS from A. Mark A visited + in-stack.
2Go to B. Mark B in-stack. Stack: [A, B]
3Go to C. Mark C in-stack. Stack: [A, B, C]
4C's neighbour is A — A is already in-stack!
!Cycle detected! Back edge C→A found.
Cycle: A → B → C → A

Sparse vs Dense Graph & Representation
Edge Density + Data Structures

Graph density = how many edges exist vs the maximum possible. This directly determines which data structure to store the graph in — adjacency list or adjacency matrix.

🏙️
Real-World Analogy
Village (sparse): few roads, most houses not directly connected. City centre (dense): every block connected to many others. Most real-world graphs (web, social) are surprisingly sparse.
Key Properties
  • ● Max undirected edges = n(n−1)/2
  • ● Sparse: |E| ≈ |V| → use Adjacency List
  • ● Dense: |E| ≈ |V|² → use Adjacency Matrix
  • ● List: O(V+E) space · Matrix: O(V²) space
Adjacency List (Sparse)
A→B, C
B→A, D
C→A, D
D→B, C
Space: O(V + E)
Adjacency Matrix (Dense)
ABCD
A0110
B1001
C1001
D0110
Space: O(V²)
Which to choose?
📋Adjacency List — BFS, DFS on social/web graphs. Most real-world algorithms use this.
📊Adjacency Matrix — Floyd-Warshall, dense graphs where O(1) edge lookup matters.
💡Rule: If |E| < |V|², use a list. If almost every pair is connected, use a matrix.
