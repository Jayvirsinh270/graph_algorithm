Breadth-First Search

Explores every node at distance 1 before distance 2, distance 2 before distance 3 — like ripples expanding across a pond. Guarantees the shortest path in unweighted graphs.

⏱ Time: O(V + E) 📦 Space: O(V) ✅ Shortest path (unweighted)
🌊
Level-by-Level Traversal
BFS uses a FIFO queue to process nodes ring by ring — guaranteeing the minimum number of hops to every reachable node.

Overview
🌊
Think of it as a water ripple
Drop a stone into a still pond — rings of ripples spread outward, each ring at the same distance from the centre before the next one forms. BFS does the same: from the start node, it visits every neighbour (distance 1), then every neighbour-of-neighbour (distance 2), and so on — never jumping ahead to a farther node until all closer ones are done.
FIFO Queue Level by Level Shortest Path (Unweighted) Invented: 1959 by E.F. Moore
🔵
Why a Queue (FIFO)?
A queue processes nodes in the exact order they were discovered. The first node in is the first out — this ensures we always handle distance-1 nodes before distance-2, distance-2 before distance-3. Swap the queue for a stack and you get DFS (depth-first) behaviour instead.
How it Works

Step-by-Step Algorithm

  1. Initialise: Create a queue. Add the start node to it. Mark the start node as visited so we never process it twice.
  2. Dequeue: Remove the node at the front of the queue. This is the current node we are about to process.
  3. Explore neighbours: Look at every neighbour of the current node. For each one that has not been visited yet — mark it visited and add it to the back of the queue.
  4. Repeat: Go back to step 2. Keep dequeuing and exploring until the queue is completely empty.
  5. Done: Every node reachable from the start has been visited exactly once. The traversal order is the BFS order.
⚠️
Common Mistake
Always mark a node as visited when you enqueue it, not when you dequeue it. If you wait until dequeue, the same node can be added to the queue multiple times — causing redundant processing and possible infinite loops.

🔑
Why BFS guarantees the shortest path
BFS visits nodes in non-decreasing order of their distance from the source. The first time BFS reaches a node, it has arrived via the fewest possible hops — because all closer nodes were already processed before any farther ones. No shorter path exists that BFS could have missed, as long as all edges have equal cost (unweighted).
Implementation

Python Code

Python BFS — Basic Traversal 
from collections import deque

def bfs(graph, start):
    # graph = { node: [neighbour, ...] }
    visited = {start}       # ① mark start visited
    queue = deque([start])  # ② FIFO queue
    order = []

    while queue:
        node = queue.popleft()  # ③ dequeue front
        order.append(node)

        for nb in graph[node]:
            if nb not in visited:
                visited.add(nb)   # ④ mark on enqueue!
                queue.append(nb)
    return order

# Example usage
graph = {
    'A': ['B','C','D'],
    'B': ['A','E','F'],
    'C': ['A','F'],
    'D': ['A','G'],
    'E': ['B'], 'F': ['B','C'], 'G': ['D'],
}
print(bfs(graph, 'A'))
# → ['A','B','C','D','E','F','G']
Python BFS — Shortest Path Distance 
from collections import deque

def bfs_distance(graph, start):
    """Returns distance (hops) from start to every node."""
    dist = {start: 0}
    queue = deque([start])

    while queue:
        node = queue.popleft()
        for nb in graph[node]:
            if nb not in dist:
                dist[nb] = dist[node] + 1
                queue.append(nb)
    return dist

def bfs_path(graph, start, end):
    """Returns the actual shortest path as a list."""
    prev = {start: None}
    queue = deque([start])

    while queue:
        node = queue.popleft()
        if node == end: break
        for nb in graph[node]:
            if nb not in prev:
                prev[nb] = node
                queue.append(nb)

    # reconstruct path
    path, cur = [], end
    while cur is not None:
        path.append(cur); cur = prev.get(cur)
    return path[::-1]  # reverse

print(bfs_path(graph, 'A', 'G'))
# → ['A', 'D', 'G']
Applications

Real-World Uses of BFS

👥

Social Networks

LinkedIn's "degrees of separation" and Facebook's "People You May Know" both use BFS to find mutual connections at distance 1, 2, 3 from any user.

🌐

Web Crawlers

Google's crawler uses BFS to discover pages link by link — visiting pages 1 hop away before exploring deeper links, ensuring broad coverage of nearby content first.

🧩

Puzzle Solving

Sliding puzzles, Rubik's cube solvers, and board game AI use BFS to find the minimum number of moves to reach the goal state.

🗺️

GPS (Unweighted)

Finding the route with the fewest road segments (not shortest distance). For minimum distance, Dijkstra's is used instead.

🔌

Network Broadcasting

Efficiently broadcasts a message to all nodes in a network at minimum hops — used in peer-to-peer networks and distributed systems.

🧬

Bioinformatics

Exploring protein interaction networks and gene regulatory networks — finding all proteins reachable within k hops from a target protein.

Key Insights

What Every Beginner Should Know

✅
When to use BFS
Use BFS when you need the shortest path by number of hops, want to find all nodes within k steps, need to check if a graph is connected, or are solving a problem where you want the fewest moves (unweighted). BFS is also ideal for level-order processing of trees.
⚠️
When NOT to use BFS
BFS is not suitable for weighted graphs — use Dijkstra's instead. It uses more memory than DFS on wide graphs because the entire frontier is stored in the queue. BFS also cannot perform topological sort (use DFS). For very deep graphs, BFS's memory use can be prohibitive.
⚡
BFS vs DFS — Quick Decision
BFS: shortest path, level-by-level, queue, broad graphs.
DFS: deep exploration, backtracking, stack, cycle detection, topological sort.
Same time complexity O(V+E) but different memory profiles — BFS uses O(width), DFS uses O(depth).
🔑
Complexity Breakdown
Time O(V+E): every vertex dequeued once (V), every edge inspected once (E).
Space O(V): at worst, all vertices are in the queue simultaneously (e.g. a star graph).
Using an adjacency list is essential — an adjacency matrix would make it O(V²).
